# WinKit - 统一桌面助手：待办 · 剪贴板 · 本地 OCR 翻译 🚀

`WinKit` 是一款专为 Windows 10 / 11（64 位）设计的轻量、美观、**本地优先**的效率工具箱。它把三件高频桌面事务整合进一个常驻系统托盘的程序：

- **TodoList 待办清单** — 毛玻璃悬浮窗，常驻桌面
- **Clipboard 剪贴板历史** — 全局拦截 `Win + V`
- **本地 OCR 翻译** — PP-OCRv6 离线识别（ONNX Runtime）+ 在线/大模型翻译，截图即翻

视觉体系采用磨砂半透明（毛玻璃），并自研贴合 Windows 11 Fluent 风格的系统托盘菜单与统一设置中心。

> 本项目基于 [li5bo5/WinKit](https://github.com/li5bo5/WinKit/releases) 二次开发，沿用 **AGPL-3.0** 协议开源。当前维护仓库：[oishijie/WinKit](https://github.com/oishijie/WinKit)。

## ✨ 核心特性

### 1. 📂 TodoList（待办清单）
* **无干扰悬浮窗**：常驻桌面，支持鼠标拖拽调整位置与大小。
* **快捷状态控制**：一键开启「置顶显示」或「鼠标穿透」（穿透后不干扰桌面正常操作）。置顶 / 穿透开关也集成在设置中心 → 待办，实时生效。
* **轻量本地持久化**：待办条目采用标准 Markdown 格式实时同步至本地 `%AppData%\WinKit\todos.md`，方便多端同步与查看。
* **双击快速交互**：双击列表空白处即可轻松添加新待办，双击已完成条目即可一键删除。

### 2. 📋 Clipboard（剪贴板历史）
* **系统级拦截（`Win + V`）**：全局低级键盘钩子接管原生剪贴板，弹出本工具专属的历史窗口，并聚焦到列表。
* **开始菜单防弹 Bug 修复**：独创 `0xFF` 虚拟击键防骚扰机制，彻底解决了拦截 `Win` 组合键时系统容易误弹出「开始菜单」的痛点。
* **文本 + 图片双支持**：不仅记录文本历史，同时监听并存储剪贴板图片（截图、复制的图片），列表中显示缩略图，双击即可回填粘贴。
* **内置截图功能**：标题栏 📷 按钮或全局快捷键 `Alt + A` 即可框选截图，截图自动存入剪贴板历史，无需第三方工具。
* **窗口钉住（Pin）**：标题栏 📌 按钮可将面板钉在屏幕上，失焦后不再自动隐藏，方便反复查看历史记录。
* **极致轻量界面**：去除了累赘的搜索框，背景不透明度支持 40% ~ 100% 多档个性化调节（默认 **80%**），提供高对比度的文字排版。
* **双击自动粘贴（回填）**：双击历史条目即可自动复制、隐藏窗口、并在 80ms 后模拟 `Ctrl + V` 物理击键，将内容直接填入原焦点输入框中。
* **隐私监听开关**：支持在托盘子菜单中一键「开启 / 关闭监听」，保障敏感工作环境的隐私安全。

### 3. 🔍 本地 OCR 与翻译
* **截图翻译（`Alt + S`）**：框选截图 → 本地 PP-OCRv6 识别 → 翻译 → 结果窗（原文 + 译文）。
* **划词翻译（`Alt + D`）**：复制选中文本 → 翻译 → 结果窗。
* **本地 OCR（`Alt + Shift + S`）**：仅识别截图中的文字，不做翻译。
* **静默 OCR（`Alt + Shift + F`）**：识别后自动复制到剪贴板，不弹窗。
* **截图到剪贴板（`Alt + A`）**：框选截图后直接存入剪贴板历史，无需翻译或 OCR，快速归档。
* **完全离线识别**：OCR 由 **PP-OCRv6 + ONNX Runtime（CPU 推理）** 在本地完成，不联网、不上传任何图像，也不需要系统装任何 OCR 语言包。
* **模型热切换**：在设置中心切换 OCR 模型后无需重启应用，引擎自动在后台重建并预热，下次快捷键即时响应。
* **小字增强**：桌面正文常只有 12~16px，而识别头按 48px 行高训练。**检出小字时自动放大重识别一遍**，两轮之间按字符数与置信度择优 —— 代价是最多跑两次推理，只在真的检出不清晰的小字时触发。
* **置信度过滤**：引擎逐行回传置信度，低于 0.5 的行（图标、边框、纹理被误检成"文字"）直接丢弃，不再污染识别结果。状态栏显示 `置信 92%` 这样的整体可信度。
* **深色截图自动反色**：按 3×3 网格投票判定背景极性，只有 ≥2/3 区域偏暗才整图反色 —— 深浅混排的截图不会因为一次误判把正常的那一半毁掉。
* **倒置文字**：方向分类默认开启，翻转截屏 / 拍屏照片这类 0° 与 180° 混淆的内容不再输出乱码。
* **超大截图兜底**：超过 3000px 的长图 / 4K 整屏等比缩到 2048px 再识别（此前是 960px，会把小字压到不可读），避免推理卡死又不至于丢字。
* **可中断**：换一次识别会真正打断上一次推理（取消传到 ONNX 逐算子检查），不会让旧任务白跑完。
* **模型缺失自动回退**：所选 OCR 模型文件缺失时，自动回退到另一个可用模型并在状态区提示。
* **可切换翻译引擎**（默认国内大模型，国内网络直连、无需代理）：
  - **国内大模型（DeepSeek 等 OpenAI 兼容）**：默认引擎，预填 `https://api.deepseek.com/v1` 端点，填 Key 即用；也可改接通义、本地 Ollama / vLLM 等任意 OpenAI 兼容服务；
  - **百度翻译**：在设置中填写 APP ID + SecretKey，国内直连、无需代理；
  - **通用 OpenAI 兼容**：自定义 Base URL（如 `api.openai.com`）；
  - **Google**：免费免 Key 端点（国内需代理）。
  - API Key / SecretKey 均使用 Windows DPAPI 加密存储，不明文落盘。
* **模型缺失自动回退**：所选 OCR 模型文件缺失时，自动回退到另一个可用模型并在状态区提示。

### 4. 🔄 剪贴板同步（兼容 SyncClipboard 官方协议）
* **跨设备剪贴板互通**：文本 / 图片 / 文件三类内容与手机端官方 [SyncClipboard](https://github.com/Jeric-X/SyncClipboard) 客户端直接互通，协议逐字对齐官方实现（hash 算法、两步上传、`Image_时间戳.png` 命名）。
* **配套服务器**：使用自部署的 [SyncClipboardCfServer](https://github.com/oishijie/SyncClipboardCfServer) —— SyncClipboard 官方同步服务器的 Cloudflare Workers 复刻（TypeScript + D1 + R2 + Durable Objects），免服务器、免流量费，免费额度内轻松支撑多设备轮询；也兼容官方协议的任意 WebDAV / 自建服务器。
* **推送时机可控**：文本复制即推；图片 / 文件默认仅入本地历史，通过资源管理器右键「同步到手机（WinKit）」显式推送（无视开关与黑名单，仅大小上限拦截）。
* **双向自动拉取**：远端新内容自动写进系统剪贴板与本地历史，推送 / 拉取成功均有托盘气泡提示，可分别开关。
* **大小与黑名单**：图片 / 文件推送上限可调，文件扩展名黑名单对齐官方上传黑名单。
* 文字 / 图片 / 文件三类内容**双向互通**的完整操作步骤，见下方「📲 手机 ⇄ 电脑 互传指南」章节。

### 5. ⚙️ 统一设置中心
* 入口：托盘右键「**设置**」，或 Todo 标题栏齿轮「**⚙**」。
* 七个分区：**通用 / 待办 / 剪贴板 / 同步 / 截图 / 翻译与 OCR / 关于**。
* **改一项存一项、即时生效**；窗口不透明度滑块拖动时主窗口实时变淡预览。
* **快捷键可配置**：翻译与 OCR 分区内可点击录制新的快捷键组合，保存后立即生效，无需手动改代码。
* 关于页显示版本、作者、项目地址、AGPL-3.0 协议与 OCR 引擎运行状态（含模型回退提示）。

### 6. 🎨 现代自研 Fluent 托盘右键菜单
* **WPF 上下文菜单接管**：彻底弃用 WinForms 的陈旧菜单，采用 WPF 自研设计系统，带来 8px 圆角、微透明磨砂白底色、高档投影与 hover 动态高亮。
* **完美的失焦自动关闭**：引入常驻后台的 0×0 像素焦点宿主窗口 `MenuHostWindow`，菜单弹出时被置于前台，点击屏幕其他任意区域即瞬间合起，无任何闪退。
* **不透明度子菜单**：托盘菜单内直接选择 40% / 60% / 70% / 80% / 90% / 100% 档位，即时刷新并保存。

## 📲 手机 ⇄ 电脑 互传指南

> WinKit 兼容 [SyncClipboard](https://github.com/Jeric-X/SyncClipboard) 官方协议，**电脑端装 WinKit、手机端装任意官方或社区客户端**即可互通。本节按「先配置，再双向传」的顺序给出完整步骤，覆盖**文字 / 图片 / 文件**三类内容。

### 步骤 0 · 一次性配置

#### 0.1 准备服务端

| 选型 | 适用场景 |
| :--- | :--- |
| [SyncClipboardCfServer](https://github.com/oishijie/SyncClipboardCfServer)（**推荐**） | 不想买服务器：部署在 Cloudflare Workers，D1 + R2 存储，免流量费、免费额度够用 |
| [SyncClipboard.Server](https://github.com/Jeric-X/SyncClipboard/releases) | 有 VPS / NAS，Docker 一条命令起服务 |
| WebDAV / S3 | 已有 Nextcloud、AList、对象存储，直接拿文件夹或 Bucket 当同步盘 |

服务端只需记住三样：**地址、用户名、密码**。电脑端与手机端必须填成完全一致。

#### 0.2 电脑端配置 WinKit

1. **开总开关**：托盘图标右键 → 勾选 **「剪贴板同步」**。
   > 这是顶级总开关，勾上才会启动后台轮询。不勾时整个同步不工作，但资源管理器右键「同步到手机」仍可用 —— 它走独立的推送通道。
2. **打开设置**：托盘右键 → **「设置」** → 左侧 **「同步」**。
3. **填连接信息**（「连接」卡片）：

   | 字段 | 填法 |
   | :--- | :--- |
   | 服务器地址 | `https://你的域名` —— **不要**以 `/` 结尾 |
   | 用户名 | 与服务器端一致 |
   | 密码 | 与服务器端一致（本机经 Windows DPAPI 加密存储，不明文落盘） |

   改完自动保存，引擎会**热重启**，不需要重启程序。
4. **确认连通**：点右侧 **「立即检查」**，状态行应出现形如 `正常 · 上次成功 18:42:10 · 轮询 5s`
5. **按需打开类型开关**（「同步内容」卡片）：

   | 开关 | 默认 | 作用 |
   | :--- | :--- | :--- |
   | 同步文本 | ✅ 开 | 文本的双向推送与拉取 |
   | 接收图片 | ✅ 开 | 手机发来的图片自动写进本机剪贴板与历史 |
   | 接收文件 | ❌ **关** | 手机发来的文件自动落盘 —— **要收文件必须手动打开** |

#### 0.3 手机端装客户端

| 平台 | 可选客户端 |
| :--- | :--- |
| Android | [SyncClipboard Mobile](https://github.com/Jeric-X/syncclipboard-mobile)（官方）、[Sync Clipboard Flutter](https://github.com/bling-yshs/sync-clipboard-flutter)、[AutoJs6 脚本](https://github.com/imgs/SyncAutojs6)、[Fcitx5 插件](https://github.com/qh7574/Fcitx5-SyncClipboard)、[Xposed 模块](https://github.com/shaklow/syncclipboard-xposed) |
| iOS | 官方[快捷指令](https://github.com/Jeric-X/SyncClipboard#ios)（手动同步 / 后台自动同步两种） |
| HarmonyOS Next | [ClipLink](https://github.com/xiebaiyuan/ClipLink) |

在客户端里填**同样的三要素**（地址 / 用户名 / 密码），并打开「上传」「下载」两个方向。

> 若服务端是 WebDAV，官方要求工作目录中再建一个 `file` 文件夹用于文件同步。**文件类型同步失败时先查这一项**；文件同步报错，原因往往不在 WinKit。

配置完成后，任一侧复制内容，另一侧默认 **5 秒内**收到（轮询间隔可在设置中调 1–300 秒）。

### 步骤 1 · 手机 → 电脑

#### 1.1 文字

1. 手机上复制任意文字（微信消息、网页、短信验证码都行）。
2. 在客户端里触发**上传**（自动同步型客户端会自动完成，手动型客户端需点一下）。
3. 电脑端 5 秒内弹出托盘气泡：`收到远端：xxx…`
4. 文字已**自动写进系统剪贴板**，同时进入剪贴板历史。直接在任意输入框 `Ctrl + V` 即可。
5. 想翻历史：按 `Win + V` 打开 WinKit 剪贴板面板，最新一条就是它。

#### 1.2 图片

1. 手机上复制或分享图片到客户端，触发上传。
2. 电脑端气泡：`收到远端图片 (1080×2400, 1.2 MB)`
3. 图片以**两种格式同时**进入剪贴板：
   * **位图** → 在 Word / 微信 / 画图里 `Ctrl + V` 直接粘出图像；
   * **文件** → 在资源管理器里 `Ctrl + V` 直接落成 `.png` / `.jpg` 文件。
4. 原图字节保存在 `%APPDATA%\WinKit\images\`，并进入剪贴板历史（列表中显示缩略图）。

#### 1.3 文件（单个）

> **前提**：设置 → 同步 → 「同步内容」→ 打开 **「接收文件」**。默认是关的，不开收不到。

1. 手机上传一个文件。
2. 电脑端气泡：`收到远端文件：报表.xlsx (2.3 MB)`
3. 文件落在 `%APPDATA%\WinKit\sync\`，剪贴板变成**文件列表**。
4. 在想要的文件夹里直接 `Ctrl + V`，文件就拷过去了 —— 不用去 AppData 里翻。
5. 同名文件重复接收会**覆盖**。

#### 1.4 文件（手机多选）

手机端多选上传时，官方协议会打成 `File_时间戳.zip` 并以 `Group` 类型提交：

1. 电脑端自动解包到 `%APPDATA%\WinKit\sync\Group_20261029184253312\`
2. 剪贴板里是解包后**每个文件的列表**，`Ctrl + V` 一次性全部拷出。
3. 同样需要「接收文件」开关处于打开状态。

### 步骤 2 · 电脑 → 手机

#### 2.1 文字（复制即推）

1. 电脑上 `Ctrl + C` 复制任意文字。
2. 只要「同步文本」开着，**无需任何其它操作**，引擎在下一轮（≤5 秒）自动推送。
3. 气泡提示 `已同步到手机：xxx…`
4. 手机端触发**下载**，文字进入手机剪贴板，直接粘贴。

> 防回环：从手机拉取过来的文字不会被再推回手机。

#### 2.2 图片（默认不自动推）

**默认行为**：复制 / 截图只进本地历史，不上传。传到手机有两条路：

**路 A · 临时打开自动推送**

1. 设置 → 同步 → 「推送时机」→ 打开 **「图片自动推送」**。
2. 之后 `Alt + A` 截图或复制图片，即自动上传。
3. 手机端触发下载。

**路 B · 走右键菜单（推荐，无需改开关）**

1. 先把图片**存成文件**（截图后在剪贴板面板另存，或直接用已有的图片文件）。
2. 在资源管理器里右键该图片 → **「同步到手机（WinKit）」**。
3. 该入口**无视开关与黑名单**，只受大小上限约束。
4. 手机端触发下载。

#### 2.3 文件（单个）

1. 在资源管理器里右键文件 → **「同步到手机（WinKit）」**。
2. 托盘气泡给出推送结果，手机端触发下载即可。
3. 该入口同样无视「文件自动推送」开关与黑名单，只拦截超过上限的文件。

> 右键菜单需先在 设置 → 同步 → 「集成」里打开 **「资源管理器右键菜单」**，安装一次即注册到当前用户的 `HKCU`，不写系统级注册表、不需要管理员权限。

#### 2.4 多文件

1. 资源管理器里**多选**文件 → 右键 → **「同步到手机（WinKit）」**。
2. WinKit 自动打包成 `File_时间戳.zip`（官方 Group 类型，内含逐文件 hash 清单，手机端可校验）。
3. 手机端下载后自行解压。
4. 只选一个文件时会自动降级为普通 `File` 类型，不打包。

#### 2.5 「文件自动推送」要不要开

设置 → 同步 → 「推送时机」→ 打开「文件自动推送」后，**复制文件即上传**。多数场景不建议开：大文件容易吃掉移动网络流量和后端配额，逐次右键更可控。

### 步骤 3 · 限制与开关速查

| 项目 | 默认值 | 位置 |
| :--- | :--- | :--- |
| 轮询间隔 | 5 秒（可调 1–300） | 同步 → 连接 |
| 图片推送上限 | 20 MB | 同步 → 限制 |
| 文件推送上限 | 48 MB | 同步 → 限制（Cloudflare Workers 单请求上限） |
| 文件扩展名黑名单 | `exe,dll,msi` 等，逗号分隔 | 同步 → 限制 |
| 推送成功气泡 | 开 | 同步 → 通知 |
| 拉取成功气泡 | 开 | 同步 → 通知 |

**关键区别**：自动推送受「类型开关 + 黑名单 + 大小上限」三重限制；右键「同步到手机」属于**显式意图**，只受大小上限约束。

### 步骤 4 · 收不到怎么办

按顺序排查，90% 的问题出在前两项：

| 现象 | 排查点 |
| :--- | :--- |
| 两个方向都不通 | ① 托盘「剪贴板同步」总开关是否勾上 ② 设置页状态行是否报错 ③ 手机与电脑填的地址 / 账号 / 密码是否完全一致 |
| 文字能通，图片或文件不通 | 「同步内容」里 **接收图片 / 接收文件** 是否打开（接收文件默认关） |
| 图片 / 文件发不到手机 | 默认不自动推：改用右键「同步到手机」，或打开对应的「自动推送」 |
| 只收到一次，之后不再更新 | 远端内容 hash 未变时不会重复拉取，属正常防抖行为 |
| 文件没收到，提示已跳过 | 超出大小上限，或被扩展名黑名单命中 |
| 状态行长期停在「等待首轮完成」 | 检查地址前缀 `https://`、结尾多余的 `/`、以及服务端存储是否已就绪 |

## 🛠️ 编译与发布

> ⚠️ 本地 OCR 的模型文件随仓库提交在 `models/`，**必须先把仓库完整克隆**（不能只下源码快照漏掉 models）。缺模型时 `VerifyLocalOcrModels` 构建目标会直接报错，并指出缺的是哪个文件。

```powershell
# 0. 还原依赖（首次必须：拉取 RapidOcrNet / ONNX Runtime / SkiaSharp 等 NuGet 包）
dotnet restore

# 1. 编译开发版（输出至 bin/Release/net8.0-windows/，含 models\ 子目录）
dotnet build -c Release
```

发布为单文件可执行（二选一）：

```powershell
# 极致精简版（Lite）：需预装 .NET 8 Desktop Runtime
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -p:PublishReadyToRun=true -o Publish_Releases\Lite

# 独立免装版（Standalone）：自带运行时，双击即用
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:PublishReadyToRun=true -o Publish_Releases\Standalone
```
